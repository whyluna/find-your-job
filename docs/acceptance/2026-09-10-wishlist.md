# 意向岗位流程与代码复核

## 设计

- `SAVED` 的用户名称改为“意向岗位”。内部状态键和数据库结构保持兼容，旧记录和旧版扩展收录无需迁移。
- 收藏与投递分开：新建默认收藏；已投递岗位可以直接补录。收藏只要求公司、岗位，支持招聘链接、JD 和标签，其他信息按需展开。
- 详情页提供“打开岗位页面”和“确认已投递”。打开链接只打开招聘网页；用户实际投递后，再登记日期、渠道、批次和实际简历。
- 确认投递使用独立事务：保存实际投递信息、追加 APPLIED 事件、重算状态一起成功或回滚。条件更新拦截重复/并发确认，归档岗位先恢复后才能确认。
- 可在岗位范围选择意向岗位、投递记录、具体阶段和已归档。仪表盘提供意向岗位入口。
- 统计与投递记录使用同一个已投递集合；准备备注、投递前沟通和投递前放弃不计入投递量、渠道/批次分布、简历过筛率与沉默投递。
- 所有本地写入更新关联页面缓存；从浏览器回到 App 时刷新外部收录。存在编辑弹窗时暂缓窗口聚焦刷新，保护未保存的输入。

## 复核中已修复

1. 手动收藏入口缺失、默认自动记投递，且没有岗位链接输入。
2. 意向岗位绑定默认简历并提示“缺少简历”；清空简历选择又被自动默认值覆盖。
3. 未投递收藏混入正式投递统计与沉默提醒，投递前放弃也被视为投递。
4. 面试门禁中的 `__INTERVIEW__`、三方事件的 `TRIPLICATE` 键未匹配，存在绕过前置阶段检查的路径。
5. 增删改后的仪表盘、统计、日历等缓存未统一刷新；扩展写入后返回 App 列表可能不更新。
6. 归档后缺少可到达的查看/恢复入口。

## 仍值得后续完善

后续处理：以下三项已在同日继续实现，详见 [三个改进点的实现与验收](2026-09-10-followups.md)。以下保留原始自查发现，便于追溯。

这些是代码复核发现的独立改进点，不属于本次意向岗位转换的阻塞项。

1. **P2：CSV 不是完整恢复格式。** `CsvImportWizard.tsx` 只按投递日期决定是否生成 APPLIED，不还原导出文件里的当前阶段、面试轮次和历史事件。因此 CSV 回导不能恢复完整招聘进度；完整恢复应继续使用 JSON。后续可在导入预检明确说明该差异，或设计独立的状态迁移模式。
2. **P2：岗位 URL 去重过度归一化。** `services.rs::canonical_job_url` 对完整 URL 转小写，路径或查询参数区分大小写的招聘站点可能误判两个职位为重复；目前没有覆盖这种 URL 的测试。后续应仅归一化协议/域名，保留路径和业务参数的大小写。
3. **产品扩展：意向岗位的计划投递日/网申截止提醒。** 目前可以保存准备备注和原链接，但没有独立于招聘阶段事件的计划日期。后续可增加计划日期和提醒，避免把“计划投递”提前记成“已投递”。
