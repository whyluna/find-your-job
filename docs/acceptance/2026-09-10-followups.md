# 意向岗位三个改进点

本文由本轮实现者整理，包含实现说明、自查和执行结果，不代表独立审查。

## 1. 投递计划与网申截止

- 新增 `planned_apply_at`、`application_deadline` 两个可空字段，采用可重复启动的增量迁移，保留旧数据。
- 新建意向岗位可展开计划字段；详情页“投递计划”可设置、修改、清空日期。服务端会校验部分更新后的最终值，拒绝计划晚于截止。
- 仪表盘展示近期计划、网申截止及已过期未处理项目，日历显示独立条目和颜色。已投递、放弃、归档后不再产生待投递提醒。
- 系统通知沿用用户主动开启的提醒设置和提前量；不会因升级自动开启权限。提醒调度依赖 App 运行，完全退出后不会发送通知。

## 2. CSV 招聘流程恢复

- 新版导出增加“计划投递时间”“网申截止时间”“流程数据”列，整个导出在同一个数据库读事务中取得一致快照。
- “流程数据”带版本号，包含实际投递日期、事件、面试时间/结果/轮次、复盘题目/回答/标签、自定义事件定义与归档状态。
- 导入前校验快照版本、结构、数量、轮次和状态重算结果；快照损坏或与表格状态/日期冲突时整批拒绝。所有写入在同一事务中进行。
- 导入时为岗位、事件、面试、题目和自定义类型重新生成 ID，正确重建父子关系，保持已有数据不被覆盖。时间字段统一保存为微秒精度 UTC，避免字符串排序改变流程结果。
- 普通表格支持中文/英文状态及已知面试轮数；导入节点明确标为“CSV 迁移”，面试详情、缺失的时间和结果待补，不会伪造回答或通过结果。面试中但没有轮数时建立一条待补充的面试占位记录。
- 预检展示每行恢复范围。实体简历、附件文件不进入 CSV，完整文件迁移使用 JSON 全量备份。

## 3. 岗位链接去重

- 协议/域名及默认端口由 URL 解析器统一；保留路径、查询参数和尾斜杠，不再将整个 URL 转小写。
- 普通页内锚点忽略，携带职位标识的 hash 路由保留，避免 SPA 招聘站点不同岗位被合并。
- 扩展收录与 CSV 预检共用这套规则。

## 自动化验收

- TypeScript 检查、34 项前端测试、77 项 Rust 测试、Clippy 和扩展生产构建通过。
- 覆盖旧库增量迁移与二次启动、日期部分更新/清空、归档与正式投递后停止待投递提醒、过期提醒和去重键。
- 真实 CSV 文件写出→标准 CSV 解析→空库导入测试通过：两轮面试、题目与理想回答、自定义事件、归档和计划日期均还原。
- 全部 11 个状态的普通 CSV 迁移测试通过；损坏快照、未知版本、状态冲突和损坏引号有回归覆盖。
- 链接测试覆盖协议/域名等价、路径大小写、参数值大小写、尾斜杠、页内锚点和 SPA 路由。

## 安装版验收

- 在真实 macOS 窗口创建虚构岗位并设置今天的计划与次日网申截止；详情显示正确日期，仪表盘同时显示已到期计划和近期截止，日历在对应日期显示正确条目。
- 确认已投递后，待投递计划/网申截止从待办消失。
- 通过 App 导出新版 CSV，删除虚构原记录，再通过界面自动映射、预检和事务导入成功恢复。投递状态、原事件时间和备注均一致；删除误记事件回到意向岗位时，原计划与网申截止也完整保留。
- 界面验收发现日期弹层会被短弹窗裁切，已改为固定定位并随滚动/窗口大小调整，保持控件在视口范围内；增加边缘翻转和滚动定位回归测试。
- 最终安装版已实看日期弹层：整月日期、小时/分钟控件完整可见，超出弹窗边界的部分不再裁切；选择与清空均正常。
- 测试岗位、事件和公司已删除，导出的测试 CSV 已移入废纸篓。数据库恢复到验收前 0 个岗位、0 个事件、3 家公司的基线，公司及设置逐行比较无变化，完整性与外键检查通过。
- 当前用户未开启系统通知；本轮没有改变该设置。通知提前量、过期处理和去重键通过自动化测试；实际系统横幅未开启验收。
